# ResinDB Pro validation contract

This document defines the release evidence required for ResinDB Pro v3.1.0 on the sole `main` branch.

## Required gates

1. `npm ci` completes with the committed lockfile on Node.js 22.
2. External resin assets pass manifest, schema, reference, duplicate, cycle and scientific-range validation.
3. ESLint and TypeScript checks pass without suppressing release-blocking errors.
4. Unit and scientific tests pass independently.
5. The production build succeeds and emits runtime JSON under `dist/data/resin/`.
6. Built JavaScript contains no resin-record sentinel strings, proving that the datasets are not statically embedded in frontend chunks.
7. HTTP smoke checks verify the SPA entry point and all manifest-declared resin assets.
8. Chromium UI validation covers authentication, Chinese/light and English/dark dashboards, empty-state recovery, product detail, scientific analytics, dependency-map interaction and mobile layout.
9. The repository branch proof must contain exactly `refs/heads/main`.
10. CI publishes `validation-evidence-<commit>` with a dashboard, metrics, logs, coverage and screenshots, then posts the commit status context `resindb/ci-evidence`.

## Evidence files

The CI evidence artifact includes:

- `validation-dashboard.html`
- `validation-summary.json`
- `build-metrics.json`
- `coverage-metrics.json`
- `ui-smoke-manifest.json`
- `ui-dashboard-zh-light.png`
- `ui-empty-state.png`
- `ui-product-detail.png`
- `ui-scientific-analytics.png`
- `ui-dependency-map.png`
- `ui-dashboard-en-dark.png`
- `ui-mobile-dashboard.png`

The screenshots are generated by the tested application in Chromium; they are not hand-authored placeholders.

## Release rule

A release is accepted only when every required gate is green on the final commit and the remote branch list contains only `main`.
