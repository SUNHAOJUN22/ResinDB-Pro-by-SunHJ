# Migrating to ResinDB Pro v3.1.0

## What changed

Resin records are no longer imported from `src/data/*.json` into the frontend dependency graph. Versioned runtime documents now live under `public/data/resin/` and are described by `public/data/resin/manifest.json`.

## Application integrations

- Deploy the complete `dist/` directory, including `dist/data/resin/`.
- Preserve JSON MIME types and do not rewrite asset requests to `index.html`.
- Configure `VITE_BASE_PATH` when the application is hosted below a repository or reverse-proxy subpath.
- Treat loader warnings as an availability signal; the application uses a deterministic fallback so that the UI remains diagnosable.

## Data maintenance

1. Edit or replace the relevant versioned JSON document under `public/data/resin/`.
2. Keep stable identifiers and valid category references.
3. Run `npm run data:manifest` to refresh hashes, sizes and counts.
4. Run `npm run data:validate` before committing.
5. Run the complete `npm run validate` gate before release.

## Removed assumptions

- Resin data is not expected to exist in JavaScript chunks.
- A successful Vite build alone is not sufficient; external-asset and HTTP smoke checks are mandatory.
- Screenshot files in release evidence are generated by Chromium CI and are not committed static placeholders.

## Compatibility

The visible product and category behavior is preserved, including the corrected `sub_pet` alias to `cat_pbt_pet`. Existing deployments must copy the new external assets alongside the application bundle.
